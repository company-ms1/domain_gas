Getting started

Sign in to your personal account and open the API tab to obtain your Base URL and API key.

Open account

Set these variables in your terminal. Copy the Base URL from your account without a trailing slash.

cURL / Shell
export BASE_URL="https://YOUR_API_BASE_URL"
export API_KEY="YOUR_API_KEY"

Send X-API-Key for balance, tariffs and orders. The fee estimate endpoint is public and needs no API key. Keep your key on your backend, not in browser code.

Check balance → estimate Energy → fetch tariffs → place an order

Energy is delegated to the wallet sending USDT. recipient_wallet in the estimator is the destination of the USDT transfer.

New: prepare a USDT transfer in one call — we check the addresses, order Energy and Bandwidth for the sender and tell you when to send.

Go to transfer preparation →

POST/v1/transfers/prepareNEW

Prepare a USDT transfer

X-API-Key required

Checks the sender (and, on request, the recipient), orders Energy and Bandwidth for the sender if needed, and tells you when the transfer can be sent.

Create a preparation → poll its status → send USDT when status = ready

Authorization: the X-API-Key header on every request.

How it works, visually →

Headers

X-API-Key Required
Your API key.
Idempotency-Key Required
A unique string, 1–128 characters. Use the same key when retrying the same request.
Content-Type
application/json

Request body

JSON
{
  "sender": "TFCyGqE4QtizzWP******Sq28dVjQtDqk8od",
  "recipient": "TCV4qdpTxoMyq******XmhH5JFxMvmT",
  "check_recipient": true
}
sender string
USDT sender address; receives Energy and Bandwidth.
recipient string
USDT recipient address.
check_recipient bool · default false
Screen the recipient for sanctions and other stop factors.

Request

cURL / Shell
curl -s -X POST "$BASE_URL/v1/transfers/prepare" \
  -H "X-API-Key: $API_KEY" \
  -H "Idempotency-Key: 94d00c23-d08e-4fc9-95e5-f23d86f46261" \
  -H "Content-Type: application/json" \
  -d '{"sender":"TFCyGqE4Qti******Sq28dVjQtDqk8od","recipient":"TCV4qdpTxo******hH5JFxMvmT","check_recipient":true}'

Response 200 — a preparation object (see below) with status = processing, or ready right away.

Statuses

statusWhat to do
processingKeep polling.
readyResources are confirmed on-chain — send the transfer.
failedThe order was not fulfilled; you can create a new preparation with a new key.
unknownThe result is not confirmed — do not create a new order, contact support.

Retries

  • Repeating a POST with the same Idempotency-Key and the same fields returns the same preparation — no new order and no new charge.
  • On a timeout or a dropped connection, retry with the same key. A new key means a new paid order.

Full example

cURL / Shell
curl -s -X POST "$BASE_URL/v1/transfers/prepare" \
  -H "X-API-Key: $API_KEY" \
  -H "Idempotency-Key: 94d00c23-d08e-4fc9-95e5-f23d86f46261" \

POST/v1/order

Order Energy

X-API-Key required

Delegates the selected Energy package to a TRON wallet and deducts its cost from your service balance.

Energy is valid for 1 hour after delegation or until the first transfer, whichever comes first.

If the wallet is not activated, we activate it before delegating Energy. Activation costs an additional 1.2 TRX.

Calculate the required Energy before ordering →

Request

cURL / Shell
curl -X POST "$BASE_URL/v1/order" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "wallet": "TYourTronWalletAddress",
    "energy": 65000,
    "trx_topup": false,
    "trx_topup_amount": 0
  }'

Parameters

wallet Required
TRON address receiving the Energy delegation — the wallet that will send USDT.
energy Required
Energy amount from the current tariffs. Before every order, use GET /v1/public/fee-estimate to calculate the required package; do not choose it at random.
trx_topup Optional
Guaranteed cost coverage. A separate 0.5 TRX fee is deducted from the service balance. The method is selected automatically: 400 Bandwidth for 1 hour or 0.345 TRX sent to the sender wallet.
trx_topup_amount Optional
Use 0.345 when enabled and 0 when disabled. This is the service denomination, not the fee: do not use 0.5 here.

Only these two combinations are valid

Coverage off

JSON
{"trx_topup": false, "trx_topup_amount": 0}

Coverage on

JSON
{"trx_topup": true, "trx_topup_amount": 0.345}

price_trx includes only Energy. The 0.5 TRX coverage fee is charged separately.

trx_topup_sent=true means TRX was sent or a Bandwidth order was accepted; delegation may still be in progress. trx_topup_blockchain_tx_id can be null until the transaction hash is available. Your client does not need to poll Netts.

Example response

JSON
{
  "price_trx": 2.8,
  "balance_trx_after": 122.7
}

Examples are illustrative; tariff and order prices may differ.
